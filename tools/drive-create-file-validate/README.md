# drive-create-file-validate

**One-line:** Offline CLI validator for Drive `create_file` JSON payloads to catch bad base64, oversized files, and missing fields before MCP upload.

**Owning desk(s):** Perfect Water / CoS / Hospitality Ops / Coding

**Location:** `tools/drive-create-file-validate/`

## Purpose

At-PET Drive uploads hit "not a valid base64 string" / tool-bridge corruption on ~10–13KB payloads. This **preflight validator** checks `*.create_file.json` files (generated by `drive-pdf-upload-prep`) before calling hospitality Drive MCP `create_file`, so bad payloads never hit the connector.

## What It Validates

For each `*.create_file.json` file, checks:

1. **Required keys present:** `title`, `parentId`, `contentMimeType`, `disableConversionToGoogleType`, `base64Content`
2. **Correct types:** Each field has expected type (str/bool)
3. **Strict base64:** `base64Content` uses only A-Za-z0-9+/= characters; decodes with `validate=True`
4. **Size limit:** `len(base64Content) ≤ --max-b64` (default 15500 bytes)
5. **Non-empty fields:** `title` and `parentId` are non-empty strings
6. **Optional PDF magic:** When `--require-pdf-magic` is set and `contentMimeType` is `application/pdf`, decoded content must start with `%PDF`

## Install and Run

### System Dependencies

None! Pure Python stdlib.

### Python Setup

```bash
cd tools/drive-create-file-validate

# No pip install needed - stdlib only
# Python 3.8+ required
python3 --version
```

### Basic Usage

```bash
# Validate all JSONs in a directory (default: *.create_file.json)
python validate.py --input-dir out/prepared/

# Validate specific files
python validate.py --input-files a.create_file.json b.create_file.json

# Custom size limit
python validate.py --input-dir out/prepared/ --max-b64 12000

# Enable PDF magic byte check
python validate.py --input-dir out/prepared/ --require-pdf-magic

# Custom output directory
python validate.py --input-dir out/prepared/ --outdir reports/
```

### Test with Fixtures

```bash
# Run basic test with synthetic valid/invalid JSONs
python test_fixtures.py
```

The tool generates:

## Exit Codes

- **0:** All files valid (safe to proceed with upload)
- **1:** Some files invalid (review `invalid.json` and fix before upload)

## Bot Integration

Bots (Perfect Water, Coding, CoS) use this workflow:

### Step 1: Prep PDFs with drive-pdf-upload-prep

```bash
cd tools/drive-pdf-upload-prep
python upload_prep.py \
  --input-dir invoices-to-upload/ \
  --parent-id 1A2B3C4D5E6F \
  --output-dir prepared/
```

### Step 2: Validate with drive-create-file-validate

```python
import subprocess
import sys

result = subprocess.run([
    'python', 'tools/drive-create-file-validate/validate.py',
    '--input-dir', 'prepared/',
    '--outdir', 'validation-reports/',
    '--require-pdf-magic'
], capture_output=True, text=True)

if result.returncode != 0:
    print("⚠️  Validation failed! Review validation-reports/report.md")
    sys.exit(1)

print("✓ All payloads valid, proceeding with upload...")
```

### Step 3: Upload valid files only with Drive MCP

```python
import json
from pathlib import Path

# Read valid files list
with open('validation-reports/valid.json') as f:
    valid_files = json.load(f)

# Upload each valid JSON with Drive MCP create_file
for file_info in valid_files:
    json_path = Path(file_info['path'])
    with open(json_path) as f:
        payload = json.load(f)
    
    # Use hospitality Google-drive MCP
    result = await mcp.call_tool(
        server='Google-drive',
        tool='create_file',
        arguments=payload
    )
    
    print(f"Uploaded {file_info['filename']}: {result}")
```

## Critical Safety Note

- ✅ **Offline only** - No Drive API calls
- ✅ **Never invents data** - Purely validates existing payloads
- ✅ **Read-only** - Never modifies JSON files
- ✅ **CI-friendly** - Exit codes suitable for automation
- ✅ **Preflight check** - Catches errors before they hit MCP connector
- ⚠️ **Use before every upload batch** - Validation is cheap; fixing corrupted uploads is expensive

## Arguments Reference

| Argument | Required | Default | Description |
|----------|----------|---------|-------------|
| `--input-dir` | One of input-* | - | Directory containing `*.create_file.json` or `*.json` files |
| `--input-files` | One of input-* | - | Specific JSON file paths |
| `--max-b64` | No | 15500 | Max base64 bytes (match MCP limit) |
| `--require-pdf-magic` | No | False | Require `%PDF` magic bytes for PDFs |
| `--outdir` | No | `reports` | Output directory for validation reports |

## Known Limitations

1. **No semantic validation** - Does not check if Drive folder IDs exist or are accessible
2. **No deduplication** - Does not check if files already exist in Drive
3. **No batch size limits** - Validates individual files only (not total upload batch)
4. **No MCP-specific quirks** - Validates standard JSON schema only

## Troubleshooting

### "No JSON files found"

Ensure files match `*.create_file.json` or `*.json` patterns. Check file extensions.

### "base64Content invalid: Contains characters outside standard base64 alphabet"

The base64 content was corrupted. Regenerate with `drive-pdf-upload-prep`.

### "base64Content exceeds max length"

PDF is too large. Options:
1. Increase `--max-b64` if MCP actually supports larger payloads
2. Re-run `drive-pdf-upload-prep` with lower `--max-b64` to force compression
3. Manually split PDF into smaller files

### "PDF validation failed: Decoded content does not start with %PDF"

File is not a valid PDF. Check `contentMimeType` or regenerate with correct source file.

## Why This Tool Exists

At-PET Drive uploads failed with "not a valid base64 string" errors when payloads hit ~10–13KB. This preflight validator catches:
- Malformed base64 (non-standard characters)
- Oversized payloads (exceeding MCP limits)
- Missing required fields
- Type mismatches

Prevents wasted API calls and partial upload failures.
